# FrameSteps Sim — Android-приложение симулятора шагомера

Нативная оболочка симулятора МВП0 (шагомер по зонам скорости). Внутри оболочки работает тот же симулятор, что и в файле `FrameSteps_SpeedSim_v3.html`: клиентский конвейер, имитация сервера (слои 6–9), сценарии, помехи, консоль конфигов. Приложение добавляет данные ядра ОС для режима «Реал»: позицию, скорость, шагомер, акселерометр, распознавание активности и признак подмены геопозиции.

Версия приложения: `3.0`. Пакет: `com.framesteps.speedsim`. Минимальная версия Android: 8.0 (API 26). Целевая: Android 15 (API 35).

## 2. Работа приложения

Приложение открывает один экран с WebView и загружает `assets/index.html`. Страница определяет мост `window.FSNative` и переключается в режим «Реал» автоматически. Четыре вкладки симулятора (Приложение, Сервер, Консоль, Итоги) работают без изменений.

В режиме «Реал» симулятор раз в секунду запрашивает у моста срез датчиков за прошедший тик и пропускает его через клиентский конвейер и имитацию сервера. Режимы «Сценарий» и «Запись» остаются доступными: сценарии с помехами проигрываются на телефоне так же, как в браузере.

Экран остаётся включённым на время работы приложения (`FLAG_KEEP_SCREEN_ON`). Работа с выключенным экраном не реализована, см. раздел 8.

Сохранение файлов (CSV сессии, запись прогона, экспорт конфигов) выполняется в каталог «Загрузки» через мост. Загрузка файлов (запись, конфиги JSON) работает через системный выбор файла.

Страница не обращается к сети, разрешение `INTERNET` в манифесте отсутствует. Переход по внешним ссылкам внутри WebView запрещён.

## 3. Источники данных и соответствие эталону

Сбор повторяет постановку слоёв 2 и 3 эталона.

| Поле среза | Источник в Android | Правило эталона |
| --- | --- | --- |
| `fix.lat`, `fix.lon`, `fix.acc` | `FusedLocationProviderClient`, приоритет `PRIORITY_HIGH_ACCURACY`, интервал 1 с | Слой 2: OS fused location, обязательный источник |
| `fix.speed` | `Location.getSpeed()`, если `hasSpeed()` | `speed_os_mps`, nullable |
| `fix.sacc` | `Location.getSpeedAccuracyMetersPerSecond()`, если `hasSpeedAccuracy()` | `speed_accuracy_mps`, передаётся в журнал, симулятор не использует |
| `fix.age` | `elapsedRealtimeNanos` фикса и текущее монотонное время | Слой 3: возраст по монотонным меткам |
| `fix.mock` | `Location.isMock()` (API 31+), ранее `isFromMockProvider()` | `mock_location`, флаг `POLICY_MOCK_DETECTION` |
| `steps` | `TYPE_STEP_COUNTER`, разность между срезами | Слой 3, шаг 4: `null` на первом тике и при откате счётчика |
| `sma`, `imuN` | `TYPE_LINEAR_ACCELERATION`, запасной путь `TYPE_ACCELEROMETER` с фильтром | Слой 3, решение Р6: линейное ускорение, `sma = среднее(abs(ax)+abs(ay)+abs(az))` |
| `act.code`, `act.conf`, `act.age` | Activity Recognition (Google Play services) | Слой 2: `WALKING`, `RUNNING`, `STILL`, `VEHICLE`, `UNKNOWN`, `null` без наблюдений |

Решения адаптера, которых в эталоне нет:

- Запасной фильтр акселерометра: низкочастотная оценка гравитации с коэффициентом `0.8`. Константа входит в версию логики адаптера (Слой 3, Р6).
- Приведение типов Play services к перечню эталона: `IN_VEHICLE` → `VEHICLE`, `WALKING` → `WALKING`, `RUNNING` → `RUNNING`, `STILL` → `STILL`. Типы `ON_FOOT`, `ON_BICYCLE`, `TILTING` пропускаются. При отсутствии подходящего типа возвращается `UNKNOWN`. Правило требует подтверждения аналитиком.
- Детектор шагов `TYPE_STEP_DETECTOR` не используется: эталон опирается на накопленный счётчик.
- Показатели `a_mag_rms` и `a_mag_var` не передаются: симулятор их не использует.
- Гироскоп не подключён: эталон хранит его для будущей двигательной сигнатуры, симулятор не использует.

Перед стартом сессии мост проверяет разрешение геолокации и системную службу. Отказ возвращается кодами `LOCATION_PERMISSION_MISSING` и `LOCATION_SERVICE_DISABLED` из карты кодов причин. Сессия при этом не создаётся.

## 4. Разрешения

| Разрешение | Назначение | Запрос |
| --- | --- | --- |
| `ACCESS_FINE_LOCATION`, `ACCESS_COARSE_LOCATION` | Позиция и скорость | При первом запуске |
| `ACTIVITY_RECOGNITION` (API 29+) | Шагомер и распознавание активности | При первом запуске |
| `WRITE_EXTERNAL_STORAGE` (API 28 и ниже) | Сохранение файлов в «Загрузки» | При первом запуске |

На Android 10 и новее файлы сохраняются через `MediaStore.Downloads`, отдельное разрешение не нужно.

Фоновое разрешение на геолокацию (`ACCESS_BACKGROUND_LOCATION`) не запрашивается.

## 5. Сборка APK

Требования: JDK 17, Android SDK с платформой 35. Gradle Wrapper входит в проект.

### 5.1. GitHub Actions (основной путь)

1. Загрузить содержимое этой папки в корень репозитория, включая скрытую папку `.github`.
2. Открыть вкладку Actions и запустить workflow `build-apk` вручную (`Run workflow`) либо сделать коммит в ветку `main`.
3. После завершения скачать артефакт `FrameSteps-SpeedSim-debug-apk`. Внутри лежит `app-debug.apk`.

Для корпоративного раннера в файле `.github/workflows/build-apk.yml` заменить значение `runs-on` на метку своего раннера. Шаг `android-actions/setup-android` нужен только на раннерах без Android SDK. При запрете внешних actions политикой организации шаги `setup-java`, `setup-android` и `setup-gradle` заменяются предустановленными JDK и SDK, сборка выполняется командой из пункта 5.3.

### 5.2. Android Studio

Открыть папку проекта через File → Open. Дождаться синхронизации Gradle. Выбрать устройство и нажать Run, либо Build → Build APK(s).

### 5.3. Командная строка

```
./gradlew assembleDebug
```

Результат: `app/build/outputs/apk/debug/app-debug.apk`.

Сборка использует репозитории `google()` и `mavenCentral()`. На корпоративной сети может понадобиться зеркало: адрес прописывается в `settings.gradle.kts` в блоках `pluginManagement` и `dependencyResolutionManagement`.

### 5.4. Подпись

Debug-сборка подписывается автоматически отладочным ключом и устанавливается на устройство без дополнительных шагов. Для выпуска на корпоративный каталог приложений нужна release-сборка с ключом организации: параметры подписи добавляются в `app/build.gradle.kts` в блок `signingConfigs`. В проект ключи не включены.

## 6. Установка и проверка на телефоне

1. Скопировать `app-debug.apk` на телефон и открыть файл. Разрешить установку из этого источника, если система запросит.
2. Запустить приложение и выдать все запрошенные разрешения. Геолокацию выбрать «Точная».
3. Включить GPS в системе.
4. Выйти на открытое место. На вкладке «Приложение» в режиме «Реал» нажать «Запустить датчики».

Контрольный перечень:

- Строка «Геолокация» показывает «работает» после первого фикса, обычно в пределах 10–30 секунд на открытом месте.
- Строка «Шагомер» показывает «ОС: счётчик шагов».
- Строка «Активность» показывает код и возраст наблюдения. Первое событие приходит через несколько секунд, на части устройств через минуту.
- Первые тики идут без шагов: первый срез шагомера по правилу эталона даёт `null`. Счётчик ОС обновляется пакетами и отстаёт от реального шага на 1–3 секунды.
- После старта скорость на спидометре и шаги растут при ходьбе.
- Разрешение отозвано или служба геолокации выключена: старт сессии запрещён с кодом `LOCATION_PERMISSION_MISSING` или `LOCATION_SERVICE_DISABLED`.
- Включённый поставщик подменной геопозиции: тики отклоняются с кодом `MOCK_LOCATION_DETECTED` при `POLICY_MOCK_DETECTION = включено`.
- Поездка на транспорте со скоростью выше `V_MOVE_MIN`: тики отклоняются с кодом `ACTIVITY_CONFLICT_VEHICLE` при условии, что ОС распознала активность `VEHICLE` и возраст наблюдения не превышает `ACTIVITY_MAX_AGE_SEC`.

Запись реальной прогулки: вкладка «Итоги» → «Запись». Файл сохраняется в «Загрузки». Его можно загрузить в браузерную версию симулятора (режим «Запись») и прогнать при других конфигах.

## 7. Обновление симулятора внутри приложения

Симулятор лежит в `app/src/main/assets/index.html` одним файлом. Новая версия симулятора подключается заменой этого файла. Мост `window.FSNative` обнаруживается страницей автоматически, при сборке ничего не настраивается. Пересборка APK выполняется любым путём из раздела 5.

## 8. Ограничения

- Работа с выключенным экраном не реализована. Переднего плана службы (foreground service) в приложении нет, система может остановить датчики при блокировке экрана. Следующий шаг: служба переднего плана с типом `location` и перенос тикового цикла из страницы в службу.
- Тиковый цикл работает в WebView. Таймеры страницы приостанавливаются при сворачивании приложения.
- Распознавание активности требует Google Play services. На устройствах без них строка «Активность» показывает «нет Play-сервисов», активность в тик передаётся как `null`, проверка `ACTIVITY_CONFLICT_VEHICLE` не выполняется.
- При отсутствии у устройства `TYPE_STEP_COUNTER` шаги всегда равны `null`, проверки шагов отключены.
- Счётчик шагов не выдаёт значение до первого шага после старта. Пока значения нет, `steps` равен `null`.
- Подмена геопозиции определяется платформой. Для API до 31 используется устаревший `isFromMockProvider`.
- Шум сред, параметры сети, `ENERGY_MAX`, 3-секундное правило каденса, упрощённый автомат клиента на порогах `UI_*` — условности симулятора, не нормы эталона. Полный перечень приведён в консоли симулятора.

## 9. Непроверенные места

Проект проверен частично:

- Страница симулятора проверена в браузере, включая ветку моста на подставном `window.FSNative` (режим «Реал», нулевые шаги, пустая активность, подмена геопозиции, сохранение файлов).
- Kotlin-код проверен на синтаксис. Компиляция против Android SDK и запуск на устройстве в среде подготовки не выполнялись: доступа к Android SDK и Maven там нет.
- Первая сборка может выявить ошибки типов или несовпадения версий библиотек. Места риска: сигнатуры `LocationRequest.Builder` и `LocationCallback` в `play-services-location` 21.3.0, свойство `Location.isMock`, `PendingIntent` с флагом `FLAG_MUTABLE`.

Версии инструментов: Android Gradle Plugin `8.7.3`, Kotlin `2.0.21`, Gradle `8.10.2`, `play-services-location` `21.3.0`.
